# UI/UX再編と責務分離 — 2026-09-20

## 対象と位置付け

[監査資料](ui-ux-audit-2026-09-20.md)を基に、Androidアプリの設定、登録、取得、検証、画面遷移を再編した。ユーザーの追加方針に従い、設定を複数画面へ分割し、重複する確認を削減した。大規模な検証と目視確認はユーザー側で実施する。

実装基点はローカル`develop`の`dedab20`と、監査・先行修正の`a2f1cd9`。作業ブランチは`agent/codex/ui-ux-refactor`、統合先は`develop`。リモートの最新状態は今回の確認対象に含めていない。

## Implemented

### 画面構成

- 一覧を起点とし、追加はFAB、設定は右上のボタンから開始する。重複していたドロワー、下部カプセル、横ページ移動を撤去した。
- 設定を「表示」「更新確認・通知」「取得・インストール」「配布元の認証」「検証環境」「データ管理」「アプリ情報」の入口に分けた。設定本体はカテゴリ別の画面が所有する。
- 登録をURL入力とアプリ確認の2段階にした。登録設定と解析詳細は確認画面内で開閉する。登録後はアプリ詳細へ進む。
- APK取得、検証、技術情報を独立した画面にした。`focusedFlow`による一つの巨大な画面の切替を解消した。
- 検証画面は進行・承認・再試行を扱い、技術証拠は展開して参照する。スキャン確認時は対象の所見を操作の近くに表示する。
- 詳細画面の主操作を状態説明の下に配置した。状態だけの表示に空のクリック操作を付けない。

### 状態と操作

- 未検査の候補は「APKを取得」と表示する。インストール済みかどうかを`versionName`の有無で判断せず、検査済みの版の関係を使う。
- 同じアプリ・同じ観測の同版／旧版候補から更新を促さない。同じタグの別観測には以前の検査を流用しない。
- 実行中・確認待ちの検証があれば、その進行確認を主操作として優先する。検証は更新がなくても独立した入口から開ける。
- リリース情報の再取得はAPKをダウンロードしない。過去のファイル名選択条件が残る場合も、取得は明示操作から開始する。
- 保存済みAPKの利用には、取得・検査済みであることと保存先の存在状態を使う。欠落・破損時には明示的に再取得できる。再取得したバイト列が既存の観測ハッシュと一致する場合だけ、その観測の保存先を復旧する。
- 検証から取得・ビルド設定・Runner設定へ進んだ場合は、同じアプリの検証へ戻る。設定保存による遷移もその戻り先を尊重する。

### 控えた確認

通常終了の確認、起動直後の通知権限要求、登録内容を繰り返す確認画面を撤去した。通知権限は設定から明示的に要求する。通常のシステムインストーラー利用者には、未利用のShizukuサービスに関する常時表示を出さない。

ローカルビルドの導入元選択、ビルド実行、スキャン所見、署名・再現性に関わるインストール条件、認証情報の削除、完全削除など、操作に必要な既存の判断は維持する。確認を全工程へ一括適用する設定は追加していない。

### 内部の責務

| 担当 | 内容 |
|---|---|
| `AppComparisonCoordinator` | 比較実行、対象照合、比較結果・証拠のトランザクション |
| `AppInstallationCoordinator` | 導入状態の再確認、導入元と実行条件、結果記録、中断した試行の復旧 |
| `ManagedAppRepository` | 既存呼び出し口と登録・取得・追跡等。比較とインストールは上記へ委譲 |
| `AppActionPolicy` | 主操作、候補の準備要否、参照APKの利用可能状態 |
| 機能別Delegate | 登録、詳細、リリース、認証、ストレージ、Runnerなどの状態・操作 |
| `ManagedAppsDelegates` / `FeatureActionGate` | 一つのイベントストアとアプリID単位の実行制御を共有して組み立てる |

Room25、保存ID、Runner API、署名・再現性・権限の判定条件は維持した。設定の旧展開状態は書き換えない。インストール・スキャンの確認状態は対象に結び付けた一時状態とする。

機能別ViewModelへの全面移行、残る登録・取得・削除処理のRepository分割、Gradleモジュール分割、大画面の一覧・詳細併置は今回の実装に含めていない。共通ViewModelと一部のHost側購読は残る。
